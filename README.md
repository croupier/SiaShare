# SiaShare Desktop

Бессерверный файлообменник поверх децентрализованной сети **Sia Storage**.
Трафик идёт напрямую между клиентами и хостами Sia: ни прокси, ни доменов,
ни хостингов, ни сертификатов подписи кода.

## Как это работает

1. **Отправитель** (`uploader-desktop`) загружает файлы/папки в Sia, нарезая их
   на чанки по 256 МиБ и сразу закрепляя (`pin_object`) каждый. Очередь лежит в
   SQLite (WAL) — загрузка 10+ ГБ переживает закрытие программы и перезагрузку ПК.
2. По завершении создаётся **SharingKey** (read-only, со сроком жизни) и
   собирается `Sia.zip`, внутри которого портативный `receiver-micro` с именем
   `S#r_<ключ>.exe` (или `S#p1_<ключ>.exe`, если задан пароль).
3. **Получатель** распаковывает архив и запускает exe. Клиент читает ключ из
   собственного имени файла, подключается к индексатору и скачивает файлы
   поштучно или единым ZIP. Регистрация и монеты получателю не нужны —
   скачивание оплачивает аккаунт владельца ключа.

## Структура

    crates/sia-core/          общее ядро: Sia SDK, крипто, чанки, ZIP
    apps/uploader-desktop/    Tauri v2 + Rust + Svelte (отправитель)
    apps/receiver-micro/      Tauri v2 + Rust + Svelte (получатель, portable)

## Требования

- **Rust** (stable) и **Node.js 20+**
- **Windows:** WebView2 Runtime (обычно уже установлен) + MSVC Build Tools
- **macOS:** Xcode Command Line Tools
- **Linux:** libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev
  patchelf build-essential libssl-dev libgtk-3-dev
- **keyring:** на Linux нужен Secret Service (gnome-keyring / KWallet)

## Быстрый старт

    # 1. Тесты ядра и БД (интернет не нужен)
    cargo test --workspace

    # 2. Шаблон получателя нужен отправителю в resources/ ДО его запуска
    cd apps/receiver-micro && npm install && npm run tauri build -- --no-bundle
    cd ../..
    mkdir -p apps/uploader-desktop/src-tauri/resources
    cp target/release/receiver-micro apps/uploader-desktop/src-tauri/resources/
    #    (на Windows: target/release/receiver-micro.exe)

    # 3. Отправитель в режиме разработки
    cd apps/uploader-desktop && npm install && npm run tauri dev

Полная релизная сборка: `./build.sh` (Linux/macOS) или `build.ps1` (Windows).

## Релизы через GitHub Actions

    git tag v0.1.0 && git push origin v0.1.0

CI прогоняет тесты, затем три облачные машины (Windows / Ubuntu / macOS)
собирают получателя, вшивают его в отправителя и публикуют черновик релиза
с установщиками. Свой Mac для сборки macOS не нужен.

`cargo fmt` и `clippy` в CI помечены как advisory: прогоните `cargo fmt --all`
локально, затем уберите `continue-on-error` и добавьте `-- -D warnings`.

## Ограничения и безопасность (читать обязательно)

- **Квота.** Бесплатный аккаунт sia.storage — 50 ГБ. Избыточность 10+20 означает
  ~3x объёма на сети: файл 10 ГБ занимает ~30 ГБ квоты. Проверка идёт до старта.
- **AppID неизменен.** `APP_META.id` в `sia_client.rs` участвует в деривации
  ключей: смена значения после релиза = потеря доступа ко всем данным.
- **AppKey** хранится в системном keychain, не в файле. Сид-фраза показывается
  один раз при регистрации и нигде не сохраняется.
- **Отзыв не мгновенный:** уже выданные токены скачивания живут до ~5 минут
  после `revoke_sharing_key`.
- **Пароль в имени файла** — это офлайн-брутфорс блоба (Argon2id 19 МиБ/t=2/p=1).
  Годятся только сильные пароли. Формат версионирован префиксом `p1_`.
- **SmartScreen / Gatekeeper.** Бинарники не подписаны: Windows покажет
  «Неизвестный издатель», macOS потребует правый клик → «Открыть». На macOS
  ключ можно положить в `key.sia` рядом с `.app`.
- **Переименование файла** мессенджером (`… (1).exe`) не ломает ключ, но если
  имя потеряно полностью — вставьте ключ вручную в окне получателя.
- **Символ # в имени файла** легален в NTFS, но в bash/zsh запускайте в кавычках.
- **Целостность.** Получатель проверяет непрерывность индексов чанков и точное
  совпадение размеров; при расхождении выдаёт ошибку, а не битый файл.
